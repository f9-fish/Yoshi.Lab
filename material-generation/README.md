# 教科書本文マスター連動：AI教材生成エンジン（Phase 1/2）

## 今回実装した範囲

最新main `b45fbee4` のアプリ・教材形式・リポジトリ内同期コードと、利用者の開発指示書を基準にしています。Google Sheets・稼働中のApps Script・Geminiの実環境は未接続です。実シートの列と既存下書きタブの仕様は、Phase 3開始前に管理者確認が必要です。

独立したNode.js CommonJSモジュールです。アプリの画面・教材JSON・XP・認証・Firebase構成・既存スタジオは変更しません。エンジンにはSheets/GitHubへの書き込み、承認、公開、Functionsエクスポート、トリガー作成機能がありません。

- `core.cjs`：本文集約、設定、共通候補、出典・設問・ストーリー検証。
- `gemini.cjs`：明示したキー・モデルで呼ぶサーバー用アダプタ、構造化JSON、通信時間・応答サイズ制限。
- `engine.cjs`：種類別生成、途中データ、再開、重複候補の除外・類似候補の警告。
- `append-plan.cjs`：既存行を変えない追記の**計画だけ**を作成。書き込み不可。
- `examples/fixture.json`：架空の本文と手作り応答。教科書の転載や実AI生成結果ではありません。
- `examples/demo.cjs`：外部通信なしの生成・変換デモ。

## 入力契約

`buildSource(master, {subject,unitId,part})` のmasterは、先頭を次のヘッダーとする二次元配列です。

```text
原文ID / 科目 / 単元ID / Part / 文番号 / 教科書本文（英語） /
日本語訳 / 重要文法・語句メモ / 生成対象 / 備考
```

- 明示的に選んだ科目・単元・Partだけを集約します。編集中の自動実行はありません。
- 原文ID・文番号は対象内で一意。合計2万文字、最大150行に制限します。
- 単元IDは実シートの文字列を維持します。論表は単元名を別途明示し、`12` と `12 不定詞(1)` を推測で同一化しません。
- `生成対象` は空なら設定の対象を使用。カンマ・読点・改行区切りで「英単語」「英C本文Q&A」「英作文」「本文正誤問題」「Discussion」などを指定できます。「全て／全種類／対象／生成する／ALL」も設定の対象を使用します。不明な値は停止し、真偽値だと推測しません。実タブの値が違えば接続前に明示マッピングが必要です。
- 現行のQ&A・正誤・Discussion同期は英C専用です。論表は初期設定でこれらを0件にし、明示的に有効化するとエラーにします。

設定は `counts, unitName, genre, difficulty, storyStyle, revision`。標準は単語15、Q&A10、英作文10、正誤10、Discussion0（任意で5など）。英作文は標準8〜12問のうち10問、変更可能で最大20問。その他は最大50問です。題材に根拠が足りない場合、指定数未満を許容して不足数・理由を報告します。

同じ本文と設定は同じバッチIDです。`revision` を明示して増やすと新しい再生成候補になり、過去の問題は更新しません。本文・設定の変更はハッシュで検出します。

## 生成と品質検証

単語・Q&A・英作文・正誤を優先し、Discussionは任意で使えます。

- すべての候補に原文ID・本文の引用・本文ハッシュ・バッチID・候補IDを付ける。
- 引用が対象の実本文に存在しない、原文IDが不明、必須項目なし、型不正、指定数超過なら、その種類をエラーにする。
- 単語は本文中の観察形と出典を必須にし、原形化・活用の対応は教員確認として警告する。読み方は未確信なら空欄にする。
- Q&Aは本文根拠と別解を保持し、疑問詞の偏りを警告する。
- 英作文は元本文の和文英訳ではなく、重要表現を使う別の物語。起承転結、連番、各文の指定表現、模範解答の重複、本文の複製を検証する。
- 指定表現は語の境界で照合する。単数複数や活用の違いを無条件に認めず、実際に使う形を登録する。登録する別解も同じ条件を満たす必要がある。
- Falseは `contradicted`、Trueは `supported` の理由分類を必須にし、Not Givenを拒否。True/Falseの数の偏りも拒否する。
- 同じ教材枠の完全重複は除外。類似候補は警告する。表現が異なる意味的な重複を完全には検出できない。

**これは文法・意味・物語の自然さを数学的に保証する検証ではありません。** 引用が存在しても設問への論理的な根拠になるとは限らず、Falseの矛盾も意味的には教員確認が必要です。実AIの品質評価は未実施です。

## 呼び出し例・再開

```js
const {generateBatch}=require('./engine.cjs');
const {createGeminiGenerator}=require('./gemini.cjs');
// キーとモデルは、将来のサーバー側設定から取得する。値をコードへ書かない。
const generate=createGeminiGenerator({apiKey:secretValue,model:verifiedModelId});
const report=await generateBatch(
  {master,selection,settings,checkpoint:previousCheckpoint},
  {generate,maxKindsPerRun:1}
);
```

キー・モデルは必須で、自動フォールバックはありません。`gemini-3.8-flash` が稼働しているとの利用者報告はありますが、本実装では実モデルIDを推測して指定しません。既存studioApiの環境やFunctionsは変更していません。

アダプタは1呼出し55秒、応答512KB、打切り応答拒否。勝手な再試行をしません。1種類ごとの分割実行とチェックポイントを使い、成功済みの種類の有料呼出しを繰り返さずに再開できます。本文・設定が変わった途中データは拒否します。

状態：未生成 → 生成待ち → 生成中 → 要確認。失敗はエラー、分割途中は生成待ちです。`生成完了` はPhase 3の教員確認後の状態として予約しており、このエンジンは自動で承認状態へ進めません。

チェックポイントには本文由来の生成結果が含まれます。永続保存、キュー、ジョブ取得権限、排他ロックはPhase 3で実装します。現在は戻り値として返すだけです。教員用の「備考」はAIへ送信しません。本文・訳・文法メモにも個人情報や秘密情報を入れないでください。

## 追記の安全契約

`planAppend(table,candidates,{ledger})` は変更前の行を複製し、末尾に新規行だけを計画します。既存値・公開状態・行順は保持。新しい問題番号は既存最大値より後で割り当てます。

- 同じIDの異なる内容、台帳とシートの不一致、未知の必須ヘッダー、数式になる文字列は停止。
- IDのない単語タブも教材枠と単語で重複検出。既存の日本語訳を更新しない。
- `assertAppendOnly` で変更・削除が0件であることを確認。
- `verifyPlanBase` で、計画後にシートが手動編集・別処理で変更されていないことを確認。
- 部分追記からの復旧は候補ID・行ハッシュ・追記台帳を使い、既存行を検査して未追記分だけ計画する。
- 計画の変更前ハッシュは排他制御そのものではありません。Phase 3では、検証と書き込みを同じロック内で行う必要があります。
- 現時点ではすべてdry-run。承認・書き込み・公開はできません。

Q&A・英作文・正誤の現行同期コードをVMで実行し、「要確認」は0件出力、テスト上で承認した行は既存形式で取り込めることを検証しています。単語同期は未確認なので同じ保証はしていません。

## Phase 3以降の具体的な実装計画

1. **実シートの列・同期コードを確認**。教科書本文マスター、英単語、英C本文QA、英作文問題、AI生成候補、AI文法下書き、AI発展教材下書きのヘッダーとサンプル行を確認する。既存の列・トリガー・公開処理を置き換えない。
2. **既存AI生成候補をジョブ・教員確認の中心として再利用**。実列に合わせて候補ID・バッチID・元本文ID・本文ハッシュ・設定・状態・追記結果の保存先を確定する。大きいチェックポイントをScript Propertiesの1値へ押し込まない。1問題ごとの行や教員限定Drive JSONなど、サイズ制限とアクセス権を確認して選ぶ。
3. **明示的なシートメニューでキュー登録**。編集トリガーは生成を実行しない。対象選択・本文ハッシュ・設定を表示して教員が生成を指示する。ロック内で同一ジョブの二重登録を防止する。
4. **認証付き生成ワーカーを接続**。既存のFirebase IDトークンをApps ScriptのOAuthトークンで代用しない。推奨案は、Apps Scriptの `ScriptApp.getIdentityToken()` のGoogle署名・issuer・audience・確認済みメールをサーバーで検証する専用経路。許可されたApps Script OAuthクライアントを固定し、既存Firebaseユーザーの教員UIDと照合する。既存のFirebase認証経路・生徒ログインには変更を加えない。この認証機能はまだ未実装。
5. **実行者と権限を固定**。手動実行と時間トリガーの実行者を識別し、誰でも所有者の権限で生成できるWebアプリにはしない。原稿・生成結果を他教員へ無条件に公開しない。サーバー側の利用制限・本文ハッシュ・ジョブIDを照合する。
6. **1種類ずつ生成して保存・再開**。1実行の時間予算を設け、期限前に途中データを保存して次のワーカーへ渡す。利用上限・通信失敗・無効JSONはエラー表示し、勝手に無限再試行しない。
7. **要確認行だけを追記**。実ヘッダーに対応させ、LockService（同じApps Scriptプロジェクト内だけで有効）で再読込→baseHash照合→追記→台帳記録を実施。複数タブの部分成功は候補IDと行内容で再開する。新規文字列はSheets APIのRAWなどで数式として実行させない。
8. **教員が修正・承認**。本文根拠・誤答の矛盾・訳・別解・指定表現・物語の順序を確認。承認時にも再検証し、修正後の候補ハッシュと確認者・日時を記録。未承認問題は公開対象にしない。
9. **既存の公開・同期を利用**。英作文・Q&A・正誤は確認済みのスクリプトに接続。英単語の同期は実コード確認後にのみ接続。Google Sheetsを正式な管理元にし、GitHub JSONだけに追記しない。Q&Aの問題とカタログは同時コミット。複数JSONのGitHub公開はSHA照合・単一コミット・force:falseを基本にする。
10. **通常本文教材との接続は別途確認**。今回の4系統には新しい本文穴埋め生成を含めていない。lessons.json/ronpyo_text.jsonとAI文法下書きの稼働中同期が未確認のため、これらを勝手に再生成しない。通常本文の追加まで行う場合は、管理者が列と括弧・別解形式を確認してからアダプタを追加する。
11. **テスト用ブランチでPhase 4/5**。既存問題の完全保持・未承認0件・二重追記・競合・部分失敗復旧を確認。既存学習画面で動作確認してから正式教材だけを公開する。Functions再デプロイや本番Sheet変更は別途承認後に実施する。

## 既存機能への影響と検証

現時点ではアプリ・教材・XPの変更なし。Phase 3以降に単語を追加すると通常4択・タイピング・ペアワーク・Dailyの単語候補が増えます。Q&Aと正誤は既存ペアワーク、正誤・DiscussionはReading Plus、英作文は既存writing画面を使います。

- 通常教材の既存Partへ追加すると問題数・完答時間が変わる。挑戦回数や5回目以降の完答条件をリセットしない。
- Dailyの本文4問は通常本文教材が元なので、今回の英作文を追加してもDailyの本文問題にはならない。単語の変更も当日の出題候補に影響するため公開時刻を決める。
- 英作文・Reading Plusなどに勝手にXPを付与しない。過去記録・ランキングは変更しない。
- 本文Q&Aの進行中ルームの問題セットを保持し、カタログと問題を同時に同期する。
- 既存Q&Aテスト6件はmainでも失敗しているため、本実装で修正しない。

```sh

node --test --test-isolation=none tests/*.test.cjs
```
