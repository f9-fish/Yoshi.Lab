# AI生成問題マスター

Issue #102 の保存先は、独立した非公開の「Yoshi.Lab AI生成問題マスター」です。従来の候補・下書きシート、教材本文マスターの共有・列・データを変更する移行はありません。従来のブラウザー内下書きは手元に残り、共有履歴への自動移行は行いません。

## 保存形式と整合性

- スキーマ 1。UUID v4 ごとに `batch_<uuid>` タブ、1行目は固定ヘッダー、以降は1問1行です。問題IDは `バッチID:種類:連番` です。列定義は `studio-functions/question-master.cjs` の `HEADER` を参照してください。
- 生成本文は SHA-256 のみ保存します。問題文・正解・訳、採用、状態、作成者 UID、UTC 作成・更新時刻、版、公開先ファイル・コミットを保存します。数式の解釈を避けるため、Sheets API では全セルを文字列型で送ります。
- タブ作成と全行挿入を Sheets の単一の原子的な `batchUpdate` で実行し、全件を読み戻して確認します。タブの一意性が重複作成を防ぎ、同じ ID で異なる内容を送ると拒否します。衝突や不整合は自動上書きしません。
- Gemini の応答後、ブラウザーが別 API を呼びます。保存完了前の離脱を警告し、失敗時は同じタブの再試行ボタンで同一IDを使えます。ブラウザーの強制終了前に保存できなかった内容は復元できません。
- 履歴は8バッチずつ検索します。絞り込み条件に合う結果がない範囲でも、次の範囲へ進めます。検索する生成日は JST です。共有済み履歴は他端末の教員から検索できます。
- 変更はバッチ版番号で検証し、Sheets の一意な developer metadata ID の作成と行更新を同一の原子的なリクエストで実行します。競合時は再検索してください。編集した問題は「要確認」に戻ります。メタデータとセル数の利用枠に達する前に保管計画を見直してください。編集競合防止用のメタデータやタブを手動削除・変更しないでください。

## 承認と公開

教員は履歴で採用状態を保存し、問題ごとに承認します。公開確認には対象単元と、バッチ内の承認・採用済み問題の件数が出ます。従来と同様、同じ単元の公開ファイルのグループを置き換えます。未承認の問題は公開されません。対象行だけ GitHub のコミット確認後に公開済みになります。

公開前にバッチを保留状態にし、使用した GitHub ファイルの SHA と操作IDを保存します。GitHub の応答が途切れた場合や Sheets の状態更新が失敗した場合は、履歴の **保留中の公開を再確認** を押してください。コミット履歴とコミット時点の教材を照合し、既存の公開を確認できれば Sheets の状態だけを確定します。元のファイル SHA が変わり、操作をコミット履歴で確認できない場合や履歴の確認範囲を超えた場合は停止します。管理者が公開ファイルとコミットを照合するまでタブや保留マーカーを操作しないでください。

## 管理者による導入準備

デプロイと本番設定の承認後、次の順番で行います。

1. 空の独立したスプレッドシートを作成し、専用の書き込み用サービスアカウントだけを編集者として共有します。スタジオの既存実行サービスアカウントから、その書き込み用サービスアカウントに対する短命トークン発行権限をアカウント単位で設定します。本文閲覧用アカウントは従来どおりです。Sheets API と IAM Credentials API が利用できることを確認します。
2. Gen 2 の既存 `studioApi` について、稼働ソースの世代と設定・IAM・トラフィックを取得します。既存の `scripts/studio-pr96-deployment.py` の `snapshot`、`matching_runtime`、`config_projection`、`source_archive` で同じ判定・差分照合を再利用できます。更新対象の ZIP は、現行アーカイブを基準にレビュー済み `index.js` と新規 `question-master.cjs` だけを反映してください。既存の共通モジュール・依存ロックは照合して維持します。
3. ステージングで、ソースと既存環境変数に加えた `STUDIO_QUESTION_MASTER_SPREADSHEET_ID`、`STUDIO_QUESTION_MASTER_WRITER_SERVICE_ACCOUNT` の2件だけを反映して動作確認します。変数を両方省略した構成では従来の生成・公開経路を使用します。いずれかを指定すると共有モードに入り、共有先の設定が不足する場合は保存・共有公開を拒否します。共有モードでは既存の公開 API が承認済みバッチを要求するため、機能を有効にする際は教員画面も同時期に反映してください。
4. 承認済みの本番更新後、上記の照合ツールで新リビジョン、ソースと差分を確認します。モデル、Secret 参照、CORS、IAM、トラフィック構成は維持します。テスト用シートで10問の保存と他端末の履歴確認を済ませてから本番の共有保存設定を使用してください。

このPRのテストはモックです。実サービスでの IAM・シート・生成・公開の確認は承認後に行います。

更新前後の読み取り専用監査は、同じ承認済みチェックアウトで実行できます。更新前は接続確認時の既知の関数ソースに照合し、異なるバージョンが稼働していれば停止します。

```bash
python3 scripts/studio-question-master-audit.py --before studio-before.json
# 承認済みの既存関数更新後に実行
python3 scripts/studio-question-master-audit.py --before studio-before.json --verify --sheet-id "$sheet_id" --writer "$writer"
```
