## 教材と保存先

`pair_text_qa.json` の21問と `pair_text_qa_catalog.json` の4セクションを利用します。英C Lesson 7：Part 1・2・3各5問、PUS6問。Sheets → Apps Script → GitHubの既存同期はそのままです。Spark版のための追加同期・サーバーデプロイは不要です。

ルーム作成者だけが公開JSONを取得し、番号順に並べ、目録のSHA-256と照合します。部屋作成時点の教材をRTDBへ固定するので、教材が再同期されても進行中の問題は変わりません。

既存ルームと分離した名前空間：

| パス | 内容・権限案 |
| --- | --- |
| `pairQaSpark/rooms/{0xxxxx}` | 匿名A/BのUID、Lesson/Part、版、件数、ヒント有無、交代設定、進捗。参加者だけ読み取り可能。質問・解答本文は含めません |
| `pairQaSpark/questions/{code}/{index}` | 固定した質問・模範解答・別解・解説。開始後の現在の出題者、または判定後の両参加者だけ当該問を読み取り可能 |
| `pairQaSpark/hints/{code}/{index}/{stage}` | 出題者が開いた段階だけ両参加者が読み取り可能 |

ホストが部屋→問題→ヒントの順に保存し、最後に `ready:true` にします。準備が終わるまで参加できません。スナップショットは保存後に変更できません。6桁コードは従来Q&Aと同じ0始まりで、既存ルーム（1〜9始まり）と重複しません。

Bは親ルームを読む前に、空いている `guestUid` だけを自分の匿名UIDへ書き込みます。先着1名だけが参加でき、第三者は部屋・参加者・質問を一覧取得できません。**参加コードを知り、最初に参加した匿名UIDをBとする招待方式**です。コードを他人へ渡さないでください。別の匿名UIDに復帰権限を引き継ぐ機能はありません。

## 進行・権限

- 既存のQ&A画面・A/B確認・タイマー・ヒント・○×・結果画面を再利用します。交代は半分（切り上げ）・1問・2問。
- RTDBのリアルタイム購読で同期します。通常時に全ルームをポーリングしません。タイマーの期限到達時だけ、確定処理をトランザクションで試みます。
- 進行はルーム単位のトランザクションです。問題番号とrevisionを検査して二重進行を防ぎ、Rules案でも「判定後に1問だけ」「出題者だけ」「スコアの増加量」を検証します。
- 開始・次問の開始時刻にはFirebaseのサーバータイムスタンプを使用します。期限後の×確定は参加者のどちらからでも要求できますが、Rules側の `now` 以前に任意の時間切れを作れない設計です。
- ヒント要求は回答者、ヒント提示・解答表示・○×・次へは出題者です。UIを隠すことだけを権限管理にしていません。
- 同じタブの匿名認証セッションとコードで再読み込み復帰します。切断中はRTDB SDKの再接続を利用します。未参加の招待は5分、部屋は作成から3時間で失効します。
- 終了・時間切れ・離脱によるXPや学習履歴への書き込みはありません。

## セキュリティ上の限界

1. **教材は公開GitHub JSONです。** 回答者への通常のルーム同期では、判定前の質問・解答を送信しません。ただし公開JSONの直接取得、開発者ツール、ホストが保持する全問データまで秘匿できません。出題者には問題データに解答も含めて送るので、出題者側の「解答を見る」は表示制御です。
2. JSONのSHA-256照合は、同期の不整合検出です。サーバー認証ではありません。改造クライアントのホストが自分の部屋に別の教材を登録することを、Spark版だけで完全には防げません。Rules案はサイズ・項目・変更不可・参加者・進行・スコアを制約しますが、公開JSONとの内容一致は検証できません。
3. 6桁コードを推測して先にB枠を取るリスクと、匿名UIDを大量生成する行為は残ります。Functions版の全体回数制限はSpark版にはありません。Sparkの接続数・容量・帯域上限に注意が必要です。成績評価や本人確認を伴う試験用途の保証はしません。
4. 有効期限はアクセス失効です。Spark版にはFirestore TTLの自動削除はありません。管理者が期限切れ部屋と対応するquestions/hintsをまとめて削除する保守が必要です。参加者には親の削除権限を付与しません。今回削除操作や本番へのアクセスはしていません。
