# AI教材スタジオの公開前監査

生徒向けはホームの **AI教材トレーニング** から開く `studio-study.html` です。配信サイトの同じディレクトリにある `studio-content.json` を読み、科目・Lesson・Partから教材を選びます。GitHub にコミットが作られた後、実際のサイトへの反映には Pages の公開処理を待つ必要があります。

公開処理はキー（前後の空白を除いた科目・Lesson・Part）が一致する教材グループを丸ごと置き換えます。同じキーへの2回目の公開は追記ではありません。他の組は保持します。共有モードでは保存済みの「承認済」かつ「採用」の問題だけを抽出します。この変更を反映したAPIは、既存グループがある場合に追加で明示的な置き換え確認を要求します。

## Cloud Shell での衝突検査とバックアップ

次は提案する架空の単元の例です。別の保存済みバッチを使う場合は、科目、Lesson、Partを教員画面に表示された値に合わせます。Node.jsが入った Cloud Shell を使用します。

```bash
work=$(mktemp -d) && git clone -q -b ops/studio-publication-audit https://github.com/f9-fish/Yoshi.Lab.git "$work/repo" && cd "$work/repo" && backup="$HOME/yoshilab-studio-before-$(date +%Y%m%d-%H%M%S)" && node scripts/studio-publication-audit.cjs --subject '英C' --lesson 'STUDIO-PUBLISH-TEST-20261127-01' --part '1' --output "$backup"
```

この操作は GitHub の最新 `main` のコミットを取得し、公開JSONの元のバイト列と、コミットID・Git blob SHA・SHA-256・対象単元をローカルに保存します。`collision: true` の場合もバックアップを保存し、終了コード 2 で停止します。SDKの秘密情報や教材本文を標準出力に表示しません。比較対象はAI教材トレーニングの公開JSONです。追加で `node scripts/studio-publication-audit.cjs --verify "$backup"` を実行すれば、保存したバイト列の照合値を確認できます。

## 教員画面で今できる操作

既存の承認済みバッチに対し、**承認済みの公開内容を確認** を押します。公開先と件数を見て、**確認ダイアログでキャンセル**します。プレビューは設定済みの問題マスターとGitHubを参照します。ダイアログを承認しない限り、この操作は教材公開・シート状態の書き込みを行いません。`preview` の `sha` はGitHubのファイルのblob SHAです。Cloud Shellのバックアップ後に公開ファイルが更新されていれば、手順を繰り返して新しいバックアップを取得します。

コードを共有・公開せずに生徒向け動作も確認したい場合は `python3 tests/studio-browser.py` のモック環境を使います。本番 `main` に公開すると、別名の架空単元でも公開サイト上で生徒に見えるため、本番での試験は別途承認が必要です。承認された場合は架空の英文、衝突のない専用キー、最小限の承認済み問題を使い、未承認問題を混ぜた状態で公開対象件数を確認します。公開後はGitHubコミットの差分が対象グループだけであること、Sheetsで対象の行だけが公開済みになったこと、Pages反映後に生徒画面で対象問題だけが見えることを確認します。

## 失敗時の確認と復旧

- **GitHubにコミットがなく、保留が残った場合**は保存されたファイルSHAと現在のSHAを確認します。変更があれば停止し、古いプレビューを流用しません。保留中の行をシートから直接消さないでください。
- **GitHubへの公開は成功し、Sheetsの更新のみ失敗した場合**は、公開済みコミットを確認し、復旧承認後に履歴の **保留中の公開を再確認** を使用します。APIは操作ID・コミット時点の教材を照合し、既に公開済みなら同じ教材のコミットを作らず対象行の状態を更新します。
- **誤公開の取り消し**が必要な場合は、バックアップのSHAと公開コミットの親・差分を照合します。対象ファイルの後続変更がない場合は公開コミットの逆差分を復旧PRにします。後続変更がある場合は、現在の `main` から対象グループだけを戻す差分を作成します。新規テスト単元なら、現在のグループの操作IDがテスト時と一致することを確認してその組だけ除去します。一致しない場合は自動的に削除しません。いずれもファイル全文の上書きを避け、復旧PRの承認・反映後にPagesを確認します。
- **履歴の扱い**として、GitHubの復旧でSheetsの公開済み記録は自動で戻りません。公開コミットと復旧コミットを記録し、履歴の修正は別途承認を得て行います。
