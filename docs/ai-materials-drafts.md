# 教科書本文マスター → AI教材生成候補（Spark対応・下書き段階）

## 作成済みのシート
既存スプレッドシート `1QK19vwZlG5_7uURKLi33W1zutKtAin5sKo8kbULVTrU` に既存タブを維持したまま
- 左端「教科書本文マスター」（sheetId=2093116001）：1文1行。原文ID、科目、単元ID、Part、文番号、英語、日本語訳、メモ、生成対象、備考
- 「AI生成候補」（sheetId=2093116002）：5種類の問題を審査するステージング表。「要確認」「採用」「却下」「転記済」
を追加。本文マスターにはユーザー提供の Lesson 7 PUS の12文と和訳を初期登録済み。

## 設計
1. 先生が本文マスターへ原文IDが一意となるよう本文を登録。教材は公開JSONやGitHubにコピーしない。
2. 先生が対象Partの行を選択して `prepareAIMaterialsMaster` を実行。空欄の原文IDと「生成対象」を補完する（既存値は上書きしない）。次に `previewAIMaterialsDrafts` で対象文数を確認。
3. 先生が外部AIへの教科書本文送信について学校の取扱規程・APIのデータ利用条件・著作権・費用を確認し、明示的に承認したときだけAPIキーを登録。
4. `generateAIMaterialsDrafts` を実行。**自動トリガーは作らない**。対象Partの本文だけがGemini APIへ送信され、返答はJSONとして検証し、単語・熟語と他の4種類を**2回のAPI呼び出しで別々に生成・検証**し、5種類すべての候補を「要確認」で新規行に追加。単語15〜25語、熟語5〜10件を目安に抽出（本文に該当語が少ない場合は水増ししない）。文法5〜8問、本文Q&A5〜8問、T/F5〜8問、Discussion3〜5問を目安とする。
5. 「採用」や「却下」は人による確認の印としてのみ扱う。**既存の「問題集」「英単語」「英C本文QA」等への自動転記とGitHub同期・アプリ公開は一切しない**。次フェーズで種類ごとの登録仕様・重複判定・公開前テストを整える。
6. True / False と Discussion はまだアプリ側の学習モードがないため、候補の作成・審査のみ。

## 既存Apps Scriptへの導入（まだ未適用）
`apps-script/ai-materials-drafts.gs` を既存プロジェクトへ追加ファイルとしてコピーし、同名の既存ファイルがないことを確認。Script Properties：
- `AI_MATERIALS_GEMINI_API_KEY`：APIキー。コードやスプレッドシートに書かない
- `AI_MATERIALS_MODEL`：利用契約上有効なGeminiモデルID（モデルの提供状況を確認）
- `AI_MATERIALS_EXTERNAL_SEND_APPROVED=true`：学校で利用可能と判断し、外部送信を承認したときのみ設定

APIキーや承認フラグが未設定ならAPIを呼ばない。API利用料金、データ取り扱い、送信できる本文の範囲を確認すること。

## 防御と限界
- 既存同期のコード・トリガー・公開フラグを変えない。
- 明示的な実行とScript Properties承認が必要。最大40文を1回の送信対象とし、テキストレスポンスはJSONとして検証。
- sourceIds照合、5種存在チェック、回答必須、T/F形式、生成内の重複キー確認。既存候補の同一Lesson・Part・種別・設問とも重複登録を避ける。どちらかのAPI呼び出し／検証に失敗した場合は候補を一切追加しない。
- 原文やAPI応答本文をログへ出さない。Script PropertiesへAPIキーを隔離。
- AIが本文を正確に理解した保証はない。先生による英語・事実・学習目標の確認が必須。
- 人手確認後の自動転記、学習アプリ用T/F・Discussionの追加、初回の実サービス試験は未完了。
- Firebase Spark/Blazeとは独立しており、Google Apps Script＋外部APIの利用条件が適用される。

## STEP 3：採用候補の安全な転記

追加ファイル：`apps-script/ai-materials-transfer.gs`。**既存ファイルは上書きしない。** Apps Scriptの同一プロジェクト内に新規スクリプトファイルを追加する。

- `AI生成候補` の **レビュー状態(N列) が `採用`** の行のみ対象。
- `previewApprovedAIMaterials()` は全転記先のヘッダーや必須値を検証し、種別ごとの予定件数をログ表示する。**この関数は読み取り専用。**
- `transferApprovedAIMaterials()` は検証後、採用行だけを転記する。成功した候補のレビュー状態を `転記済` に変更する。
- 転記された教材の公開状態はすべて `下書き`。既存同期関数は呼び出さない。
- 既存シートの既存行を上書きしない。英単語は科目＋Lesson＋Part＋語句、Q&Aは科目＋Lesson＋Part＋英文質問／生成ID、専用下書き表は候補IDで重複チェックする。重複は追加せず、候補の `採用` を保留するので手動確認する。

| 教材種別 | 行き先 | 注意 |
| --- | --- | --- |
| 単語・熟語 | `英単語` | G列の公開設定=`下書き`。カタカナ読みは未入力。 |
| 本文Q&A | `英C本文QA` | L列の公開状態=`下書き`。Part内で採番。 |
| 文法・穴埋め | `AI文法下書き` | 教科書用の日本語訳が生成候補にないため、既存`問題集`へ直接転記しない。訳を追記・確認後に次の工程で対応。 |
| True / False・Discussion | `AI発展教材下書き` | アプリ側の新モードが完成するまでは隔離。 |

**初期検証**：架空の採用候補5件を用いて、5種類・4転記先への登録、`転記済`への状態更新、未採用候補の保持、同じ処理の再実行で二重登録されないことをモックテストした。Google Sheets本番への転記はまだ行っていない。

注意：Google Sheetsの複数タブへの一括書き込みはトランザクションではない。途中でエラーが出た場合、転記先に既に追加されている行と候補の状態を確認すること。基本的な重複検出はあるが、同じ内容を微妙に書き換えた場合や、人が転記先を編集した場合の全ケースは自動では保証できない。
