# Yoshi.Lab AI教材スタジオ（第一段階）

## 現状

先生専用の**独立したGoogle Apps Scriptウェブアプリ**。生徒用GitHub Pages・Firebaseには変更を加えない。

- Lesson／Part別の原文・AI候補・文法下書き・発展教材の件数をまとめて表示
- AI生成候補20問など、既存の「AI生成候補」シートを画面で閲覧
- 未転記の候補に対して「採用／却下／未確認」を保存
- **転記済の候補は変更不可**。二重登録を防ぐ
- **AI生成・GitHubへの公開・Firebase・XP付与は一切行わない**
- **教科書本文をGemini等の外部AIへ送信しない**
- メールのホワイトリスト認証を全サーバー操作で実施（フロントのボタン非表示だけに依存しない）

## インストール（既存のApps Scriptプロジェクトには入れない）

1. Google Apps Scriptで**新しい独立したプロジェクト**を作成。名前を `Yoshi.Lab Teacher Studio` などにする。
2. `apps-script/teacher-studio.gs` を `コード.gs` に全文貼り付ける。
3. HTMLファイル `teacher-studio` を作成し、`apps-script/teacher-studio.html` の内容を貼り付ける。HTMLファイルの名前は `teacher-studio`。
4. **プロジェクトの設定 → スクリプト プロパティ**に `STUDIO_ADMIN_EMAILS` を追加。値には管理者本人のGoogleアカウント（例：`teacher@example.edu`。ダミーであり実際には自分のアドレス）を指定。複数はカンマ区切り。**GitHubやAPIトークンをHTMLに貼らない。**
5. **デプロイ → 新しいデプロイ → ウェブアプリ**。次のユーザーとして実行＝**ウェブアプリケーションにアクセスしているユーザー**。アクセスできるユーザー＝可能なら**学校ドメイン内**、それ以外はGoogleアカウント所有者に制限。誰でも匿名アクセスは不可。
6. 管理者本人のGoogleアカウントで認可・起動する。最初にGoogleスプレッドシートへのアクセス許可が求められる。シートの閲覧・編集権限があるアカウントで使う。
7. 既存の「教科書本文マスター」「AI生成候補」等が表示されるか確認する。テストでは既に「転記済」の項目は変更不可になっている。

## セキュリティと運用上の注意

- アクセスは `Session.getActiveUser().getEmail()` と `STUDIO_ADMIN_EMAILS` を**サーバー側で照合**。メールアドレスを取得できない環境では拒否。
- 実行ユーザー自身のGoogle Sheetsアクセス権も必要。学校の管理者ポリシーによってはWebアプリのデプロイ方法を調整する必要がある。
- シートは `1QK19vwZlG5_7uURKLi33W1zutKtAin5sKo8kbULVTrU` の固定IDを参照。
- `reviewTeacherStudioCandidate` は「AI生成候補」N列だけを書き換える。現在「転記済」の既存20問は編集不可で、他の教材・GitHubの公開には影響しない。
- WebアプリURLの秘匿だけにアクセス制御を依存しない。HTMLは先生の管理者認証成功後に返し、各リクエストでも管理者確認する。
- 既存アプリの `doGet` と競合させないために**新しいGASプロジェクト**を使う。
