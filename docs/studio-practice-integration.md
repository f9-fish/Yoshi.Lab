# AI教材を既存Practiceへ追加する

## 保存と履歴

科目・Lesson・Part は既存のバッチ属性を使います。Sheets は引き続き `batch_<uuid>` 1タブにつき1回の生成です。タグ付きの行を使い、生成ごとに6タブを作る方式を避けます。教員画面では行の種類を表示し、履歴で種類を絞り込めます。

| 行の種類 | 保存する内容 | 既存の画面 |
| --- | --- | --- |
| `source` | 生成開始時点の入力原文、科目・Lesson・Part、サーバーの作成日時、ハッシュ | 教員の共有下書き履歴 |
| `vocabulary` | 単語、意味、解説 | 単語Practice |
| `idiom` | 熟語・重要表現、意味、解説 | 単語・熟語Practice |
| `cloze` | 括弧で空欄を示す英文、日本語訳、解説 | 既存の穴埋めタイピングPractice |
| `qa` | 根拠のある英文質問、短い模範解答、日本語訳・解説 | 既存の英作文対策の入力・フィードバック画面 |
| `discussion` | 意見を求める英文質問、解答例、日本語訳・解説 | 既存の英作文対策の入力・フィードバック画面 |

本文は生成応答で置き換えず、ブラウザーで生成開始時に取得した値を、問題行と同じアトミックな保存リクエストに含めます。原文は原則として読み取り専用です。訂正して再生成すると新しいバッチ・作成日時になり、原文の異なる版が履歴に残ります。既存タブはそのまま読めます。旧バッチにはハッシュしかないため原文は復元できません。本文を含むファイルの共有は既存の教員用アクセスに限定してください。

新しい教員画面は単語・熟語・文法・クローズドQ&A・オープンQ&Aを各2問リクエストします。旧クライアントの5種類、過去のTrue/False、公開済み行は引き続き読めます。編集・承認では既存のバッチ版番号を使い、既存の公開済み問題の編集を拒否します。

## 公開とXP

`studio-content.json` では既存グループの各配列に追記します。正規化した科目・Lesson・Partと種類・問題文で重複を検査し、単語・熟語は同じ問題として照合します。数値形式の `Lesson 8` と `8`、`Part 1` と `1` は同じ単元です。旧教材の値を変更せず、重複行は今回の公開済み対象から除外します。承認済みかつ採用済みの新規問題のみ、従来のファイルSHA・バッチ版・コミットによる復旧手順で公開します。

単語・熟語と文法は、英C・論表の既存モード選択に表示する追加問題から、従来のPracticeを開きます。この追加セットはXPや学習記録を送信しません。通常セットを別に維持することで、既存問題数やXPの初回・満点判定、Dailyの母集団を保ちます。

クローズドQ&Aは登録済み解答と一致すれば正解、別の表現は要確認とします。オープンQ&Aは解答例を見て自己確認し、正誤を自動判定しません。既存のペア教材 `pair_text_qa.json` と対応するCloud Functionsには専用の進行・採点・XPがあるため、この段階では接続しません。対人練習が必要になった場合は、ペアサービス側で別途問題供給と採点を設計します。AI追加問題は既存のお気に入りの問題台帳に登録しません。

公開JSON・既存のApps Script同期ファイル・Sheetsの過去データは移行不要です。生徒画面は公開ファイルだけを参照します。追加ファイルが取得できなくても通常Practiceを使用できます。既存のデプロイガードはこの機能の実行ソースを対象にしていないため、承認後の適用前に実行ファイル差分とデプロイの事前確認を更新してください。

## 規模

1バッチ10問と本文1行のグリッドは13行×20列です。6タブ方式よりタブ数を抑えられますが、履歴検索は従来どおり8タブ単位で、バッチ数に応じて読み取りが増えます。長期化する場合は本文の不変版と問題行のID・版番号を保持したまま、種類・科目・単元の索引を用意する方式を検討します。公開JSONが増えた場合も、配信サイズを確認してから分割を検討します。
