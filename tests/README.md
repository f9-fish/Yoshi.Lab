# 既存動作の回帰テスト

Node.js 24で、リポジトリのルートから実行します。外部パッケージのインストールは不要です。

```sh
node --test --test-isolation=none tests/*.test.cjs
```

この環境では既定の子プロセス方式だとファイル単位の結果だけが報告されるため、
`--test-isolation=none` を指定し、個々のテスト件数・成否を確認します。
各テストは独立したVM・データストアを作り、アプリ側の状態を共有しません。
現時点では114件（Daily 20件、曜日チェック・週間日数7件、ホームのDaily表示8件、週間報酬15件、ランク16件、通常XP・共通計算比較21件、教員XP比較13件、過去シーズン14件）です。

## 対象

- 通常XPの倍率・30 XP上限、1〜4回目、5回目以降の完答条件。
- 科目・Lesson・Part・モード別の回数、旧記録、不正な記録、時系列順、週・シーズン集計。
- Dailyの全11段階の得点表、画面の結果処理から記録保存・XP集計まで。
- 科目別2回制限、重複予約、離脱時の警告、再読み込み後の回数消費・0 XP。
- 完了保存の再試行、入力検証、教員の3回目以降の練習、同日の問題再利用。
- 全ランクの閾値、Ⅲ・Ⅱ・Ⅰの境界前後、レディアントの10位・11位境界。
- 過去シーズンXPと共通APIのseasonXPの一致、シーズンをまたぐ挑戦回数、期間境界、過去シーズンの表示。
- Daily完了日の曜日チェック、月〜日の週間達成日数、同日の重複、途中離脱の除外、年境界、保存直後の表示更新。
- 週間3・5・7日でそれぞれ100・200・500 XP（合計800）、再同期の冪等性、週・年・シーズン境界、全画面の集計一致。
- ホームのDailyカードの達成曜日、同日重複・途中離脱の除外、未ログイン・取得失敗表示、アカウント切り替え時の古い取得結果の破棄。

ホームの達成曜日は `home-daily.js` が共通の `weekly-daily.js` と本人の保存済み記録を使って表示します。
表示処理は読み取りのみで、XP・挑戦回数・保存内容を変更しません。

## 週間達成報酬

`weekly-daily.js` を認証モジュールより先に読み込み、Daily画面・共通XP・教員画面・過去シーズンで共用します。
日本時間の月曜〜日曜で、保存済みのDaily完了記録を日付ごとにまとめます。英C・論表のどちらかを完了すれば1日です。
同日複数回・両科目の完了は重複しません。途中離脱、将来日、形式不正な日付は対象外です。
新報酬は2026年11月2日開始週から対象にし、それより前の週には遡及加算しません。

各段階の報酬を達成日のXPとして毎回導出し、累計・週間・シーズンに含めます。
報酬専用のFirebaseレコードや新しい保存フィールドは作らず、既存のleaderboard集計値へ含めます。
同期のたびに加算する方式ではないため、再読み込み・複数端末で同じ段階を重ねて加算しません。
元の完了記録を教員がリセットした場合は、再集計時に報酬も実際の達成日数に合わせて減ります。
これは既存のクライアント集計を拡張する実装であり、本番Security Rulesによる検証は未確認です。

## 本番への接続を行わない仕組み

`helpers/app-harness.cjs` は既存ソースを読み取り、Node.jsのVMで実行します。
アプリファイルは変更しません。`account.js` のFirebase importだけをメモリー上で除き、
同名APIをメモリー内ストアへ置き換えます。Firebase SDKをロードせず、認証情報も使いません。
時刻とユーザーは架空の固定値です。Dailyは既存HTMLの実際のインラインスクリプトを実行し、
`fetch` は許可した4つのローカル教材JSONの読み取りだけを実装しています。
VMにネットワークAPI・Node.jsのrequire・processは渡しません。

XPやランクの計算式をテスト側へ移植せず、既存の関数・APIとDaily結果ハンドラーを呼びます。
期待する境界値・得点表は明示した固定値です。
教員と過去シーズンの比較は、該当HTMLから対象関数を取り出します。
1行関数と、終了の波括弧をインデントなしで独立した行に置く複数行関数に対応します。
ソース構成が変わり抽出できなくなった場合はテストを失敗させ、追従を促します。

## 修正済みの不一致と残る検証不足

教員画面・過去シーズンに関する以前の不一致テストは、修正後の一致を検証する期待値に更新済みです。

1. Daily満点記録1件は共通集計・教員画面・過去シーズンのすべてで500 XPです。
2. 同一セットの途中終了5件（各3正解）は共通集計・教員画面・過去シーズンのすべてで12 XPです。
3. `KNOWN GAP`：Daily完了APIは「0正解・999 XP」をクライアント側で拒否せず保存します。共通集計時には500 XPに制限されます。
   本番のFirebase Rulesがこの入力を拒否するかは未確認です。

3の問題は今回修正していません。将来修正する場合は、別の変更として仕様を決め、該当する期待値も更新してください。

過去シーズンの比較では、共通APIの時計だけを対象シーズン内に固定して実際のseasonXPと比較します。
全履歴で挑戦回数を数えた後に対象期間を選びます。期間の開始・終了は両端を含み、シーズン境界で回数をリセットしません。
表示テストは、終了済みシーズンの逆順表示、修正後XPの描画、過去の最終レディアント順位を表示しない仕様を確認します。

## 検証範囲の限界

DOMは最小限の代替実装です。実ブラウザーの表示・操作性・音声・Googleログインは検証しません。
Daily結果のテストは正誤の配列を与えて実際の結果処理を実行します。入力欄の操作による採点は対象外です。
Firebaseの代替トランザクションは単純な原子的更新で、SDKの通信・再試行やサーバー競合を再現しません。
Rules、Firebase Emulator、Apps Script、デプロイは使用しません。
将来は本番から隔離したEmulatorで権限・競合テストを追加できます。

教員画面の `xpFromRecords` は共通集計に合わせて修正済みです。
13件の比較テストでDaily加算、途中終了・完答、履歴順序、モード別の倍率・上限、旧記録、
集計による元配列の非変更を確認します。
過去シーズンのXP集計も共通計算に合わせて修正済みです。
Dailyの曜日チェック・連続日数表示の日付判定も修正済みです。
週間報酬を共通計算・教員画面・過去シーズンへ追加しています。
Dailyの採点・挑戦回数制限、現在のランキング順位・学年の扱い、依存定義、CI、通常学習のXP倍率・ランク・Daily得点表は変更しません。
